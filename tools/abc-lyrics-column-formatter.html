ABC Two-Column Lyrics Formatter

  • Paste ABC notation into the input area, or open one or more .abc or .txt files. ABC files can also be dragged and dropped onto the Input ABC card.
  • The utility formats multi-stanza W: lyrics into two columns.
  • Click Format Lyrics. The utility examines every tune independently. Tunes with only one detected W: stanza are left completely untargeted.
  • A stanza boundary is recognized when a blank W: tag is followed later by another non-blank W: tag, or when a non-blank W: line starts with a stanza number such as 2., 3., or 4). Only uppercase W: fields are treated as unaligned stanza lyrics; lowercase w: fields aligned beneath the notes are ignored. Blank W: tags are used as manual stanza spacers and do not count as rendered lyric lines. When consecutive numbered stanzas have no blank W: spacer between them, the formatter automatically adds a modest visual gap between stanzas; if a blank W: spacer is already present, no extra automatic gap is added.
  • The formatter calculates the two-column layout directly from the ABC W: stanza structure. Stanzas are kept intact and divided into contiguous column groups. The formatter measures the widest lyric line in each column independently, chooses the largest safe common font size, and adjusts the second-column X position to make the best use of the available width. The right column also includes a one-line vertical compensation based on the active %%wordsfont size so its first stanza aligns more closely with the first stanza in the left column. No abcjs rendering library is required by this utility.
  • The generated CSS is inserted at the very top of the complete ABC inside a %%begincss / %%endcss block. Each tune is targeted through its normal #notationN container and also directly through the tune SVG. The direct SVG selector uses the tune title plus the exact number of rendered W: lines, and also includes a common article-reversed title variant (for example Banks of the Bann, The and The Banks of the Bann). This keeps the formatting active during ABC Transcription Tools PDF export when each SVG is copied out of its notation container before rasterization. Existing ABC content is otherwise preserved.
  • If the ABC file header already contains one or more %%begincss / %%endcss blocks, the formatter removes those header CSS blocks completely and replaces them with the newly generated lyric-column CSS block. CSS blocks inside individual tunes are not removed.
  • Copy Results copies the complete processed ABC. Save ABC File saves it as an ABC file.
  • Open in ABC Transcription Tools is enabled only when the processed ABC can be compressed into an ABC Transcription Tools share link of 8100 characters or less.
  • The formatter checks the width of every W: lyric line before generating the CSS. The left and right columns are measured separately. A 14px lyric size is the normal baseline, but the formatter may automatically increase it up to 17px when both columns still fit comfortably. Long lines are reduced only as much as needed. The 800-unit fitting model establishes a safe minimum second-column position, while the generated SVG CSS allows the second column to move farther right automatically when a tune is rendered substantially wider, making better use of the available page width without changing the vertical stanza positioning.
  • The generated CSS leaves the original lyric SVG height intact and forces overflow to remain visible. The second-column transforms are also applied directly to the lyric SVG, allowing ABC Transcription Tools PDF export to rasterize the same two-column layout shown on screen.
  • To reduce the size of the generated header CSS, selectors that use the same lyric font declaration or the same overflow declaration are automatically combined into shared CSS rules. Tune-specific stanza transforms remain separate so their positioning is unchanged. The generated CSS is formatted with one selector per line where practical, indented declarations, and blank lines between rules so it is easier to read and edit by hand.
  • Rendering large tunebooks: The two-column layout can generate a substantial amount of tune-specific CSS, especially for tunebooks containing many songs with multi-stanza lyrics. As a result, opening or re-rendering a large processed tunebook in ABC Transcription Tools may take considerably longer than rendering the original ABC. This is expected; allow the rendering process time to complete.
